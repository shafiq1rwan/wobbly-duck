# Asset spec

What the game needs, in what format, and how each file plugs into the code. UI look and layout
are in [UI_SPEC.md](UI_SPEC.md); the visual reference is
[reference/ui-reference.png](reference/ui-reference.png).

## Style guide (all art)

- Original flat 2D cartoon: simple rounded shapes, minimal detail, at most two flat tones per
  colour (base + one shade). No gradients, textures, noise, glossy highlights or drop shadows
  on gameplay objects.
- **Thick dark navy outline** (`#13266A`–`#1E2A4A`), consistent across assets: about 3% of the
  object's width (the duck's outline is ~9 px on a ~300 px wide duck).
- Light comes from the top-left; shading sits on the lower-right.
- Gameplay objects (duck, obstacles, stars) are more saturated and higher-contrast than the
  background, which stays pastel and calm.
- Starting palette: duck `#FFE078`, beak `#FF994A`, water `#43BDF0`, rock `#7389A6`,
  log `#B9794B`, star/crown `#FFE45C`, outline navy.
- No text inside images except the logo.

## Technical rules

- **Transparent PNG with real alpha.** No white or checkerboard background baked in. (If a
  generator can only output white backgrounds, deliver a strip and convert it with
  `tools/process-duck-strip.py`, or a similar flood-fill matte.)
- **Export at 2× world size.** 1 world unit ≈ 1 CSS px at 1280×720, so a 64-unit object is
  exported at 128 px. Canvas sizes below already include the 2×.
- **Exact canvas size and pivot** as listed, so code doesn't need per-file offsets. Spritesheets
  are one row of equal cells, every frame aligned on the same pivot.
- Deliver sources to `assets-src/` (kebab-case). `tools/optimize-images.py` crops, resizes and
  converts them to WebP in `public/assets/`; the game loads only those. Keep the first load small.
- Record each asset's source (tool, prompt, or licence) in `docs/ASSET_LOG.md` — **not** in
  `public/`, which ships with the game.
- Budget: the first load is ~700 KB and the Poki zip ~1.3 MB; keep it that way. Art needed only
  later (skins, lake scenery) loads on demand. Unused art stays out of `public/` (`UNUSED` list in
  the optimiser).

### Effects (Phase 2)

Splashes, ripples, spray and speed lines are **procedural** (pooled particles and water
springs). No files are needed. Optional: `splash-sheet.png` (1024×192, 4 cells of 256×192,
pivot at bottom centre = waterline) for a landing splash if the procedural one isn't charming enough.

### Audio (Phase 2 and 4)

Short, soft, playful. Mono, 44.1 kHz, `.mp3` (plus `.ogg` optional), normalised so no effect is
louder than the others. Files in `public/assets/audio/`.

**Current state:** every effect is synthesised in code (`src/core/Audio.ts`): jump, double jump,
dash, splashes, hit, click, pickup, bonus, crate, peeps, boing, ribbit, fanfare, popper, revive and
unlock. No files are required; recorded files can replace them one by one. Music doesn't exist yet.

## Delivery checklist

1. Real transparency, exact canvas size, pivot as specified.
2. Source in `assets-src/` and an entry in `tools/optimize-images.py` (audio in `public/assets/audio/`), kebab-case name.
3. Source and prompt or licence recorded in `docs/ASSET_LOG.md`.
4. Game checked at desktop and portrait sizes with `?debug`: hitboxes still match the art and
   obstacles read clearly against the background.
